## 联调修复：`showShareMenu:fail no permission`（19:33 开发者工具报错）

### 根因（两层）
1. **微信侧权限不足**：`showShareMenu` 一次性申请 `menus:['shareAppMessage','shareTimeline']`，但 `shareTimeline`（朋友圈）需额外权限——页面声明 `enableShareTimeline` + 开发者工具本地设置勾选 + **公众平台后台开通「分享到朋友圈」能力**（个人主体常未开通）。任一不满足，微信拒绝整个调用，**连基础「转发给好友」也一并失效**。
2. **代码侧缺陷**：`uni.showShareMenu` 无回调时返回 Promise，失败即 reject 且未被捕获 → `UnhandledPromiseRejection`（真机计异常上报）。

### 处置
- 新增 `src/modules/share.js`：`enableShareMenu()` 封装，采用「先全量、失败降级」策略（`fail` 回调触发时回退为仅 `shareAppMessage`）；显式 `success`/`fail` + `try/catch`。
- `SHARE_TIMELINE_ENABLED` 常量（默认 false）控制朋友圈；后台开通后改一处即启用，业务代码零改动。
- `pages.json` 四个分享页补 `enableShareAppMessage` / `enableShareTimeline` 声明。
- 四页 `onReady` 改为 `Share.enableShareMenu()`，移除裸调。
- `onShareTimeline` 钩子保留（仅用户实际点击时触发，不会引发调用失败）。

### 产物验证
- 构建通过（12s，429KB）。
- 页面 JSON 已含两个 enableShare 字段；`grep showShareMenu` 仅命中 `modules/share.js`，无裸调残留。
