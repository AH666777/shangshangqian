## [20:40] 修复 Daily self-check 项目编译错误（CJS/ESM 混用）

报错：`App.vue:3:7 "default" is not exported by ".../config/index.js"`。

### 根因
`config/index.js` 用 `module.exports`（CommonJS），而 `App.vue` / `pages/index/index.vue` 用
`import config from './config/index'`（ESM）。该文件所在 HBuilderX 5.26 的 uni-app Vue3 编译器
（Vite，路径 `E:/LeStoreDownload/2297-.../HBuilderX/plugins/uniapp-cli-vite`）**未内置任何 CommonJS
转换插件**（无 @rollup/plugin-commonjs / vite-plugin-commonjs，已核实），因此：
1. `import` 导入 CJS 文件 → 编译期报 "default is not exported"；
2. 源码里残留的 `require()` → 小程序端运行时 `require is not defined`。
错误只显示 App.vue 是因为编译在第一处中止，pages 里的 `api/cache/date/feedback` 导入同样会炸。

### 修复（直接改动，未加 .bak）
统一为 ES Module —— 11 个文件：`config/index.js`、`utils/api.js`、`utils/adapter/index.js`、
`adapter/mock.js`、`adapter/unicloud.js`、`utils/mock/{seed,storage,streak}.js`、
`utils/{date,cache,feedback}.js`：`module.exports =` → `export default`，`require()` → `import`。
- `adapter/index.js` 原来的**运行时动态 `require('./mock')`/`require('./unicloud')` 懒加载**改为
  静态 import + 运行时二选一（ESM 下无法动态 require），已确认两个模块顶层无副作用。
- **必须写全 `.js` 扩展名**：Node 的 ESM 不做目录索引补全，`'../../config/index'` 会
  `ERR_MODULE_NOT_FOUND`（Vite 能解析，Node 不行）。
- 云函数目录 `uniCloud-aliyun/cloudfunctions/**` 保持 CommonJS 不动（Node 运行时）。

### 连带修改：3 个 Node 自测脚本（原来 require utils，ESM 化后会失效）
`pages.selftest.js` / `uniapp-logic.selftest.js` / `feedback.selftest.js`：
改为在 async 主流程里 `const api = (await import('./utils/api.js')).default;`。
`unicloud.selftest.js` 只测云函数，未动。
