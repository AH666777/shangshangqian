## 二、部署架构：两个配置层（关键概念）

这是本次最容易混淆、也最容易踩坑的地方，必须区分清楚：

| 配置层 | 文件/位置 | 生效场景 | 是否入库 |
| --- | --- | --- | --- |
| 本地调试层 | `cloudfunctions/yqsss-auth/.env` | 仅在 HBuilderX「本地运行云函数」时由 HBuilderX 注入 `process.env` | ❌ 已被 `.gitignore` 排除 |
| 云端运行层 | uniCloud 控制台 → 云函数配置 → 环境变量 | 部署后的云函数真实读取来源 | — |

函数代码本身只做一件事：`index.js:100` 读取 `process.env.WX_APPSECRET`。它**不关心变量来自哪一层**，谁把 `process.env` 填好，它就用谁。

> 结论：本地 `.env` 填对 **≠** 线上可用。**云端必须在 uniCloud 控制台再配一次同名变量**，否则线上 `wxLogin` 会抛 `1099 云函数未配置 WX_APPID / WX_APPSECRET`。

## 四、踩坑与修正记录

### 4.1 文件命名歧义：`.env` 与 `env`

排查过程中曾出现「本地文件明明填了、检查却报空」的反复。根因是编辑器 Tab 显示与实际文件名存在视觉歧义，排查时需**以磁盘真实路径为准**，不要凭 Tab 标题判断。

**规范**：本项目统一使用 `.env`（带点），`find . -name '.env'` 与 `git check-ignore` 双重确认。

### 4.2 AppID 单字符错误：`b5` vs `b9`

云控制台录入 `WX_APPID` 时，一度出现 `wx5a7366b9deaa5ac8`（`9`），而真实值（manifest / project.config / 本地 `.env` 三处一致）为 `wx5a7366b5deaa5ac8`（`5`）。

**影响**：appid 错一个字符，微信 `jscode2session` 直接返回 `40013 invalid appid` 或 `40029`，登录必败。
**修正**：控制台改为 `wx5a7366b5deaa5ac8` 后保存并重新部署。

**规范**：appid 与 secret 一律**复制粘贴**，禁止手打；保存后逐字符与 `.env` 比对一次。

### 4.3 真实 AppSecret 误写入 `.env.example`（安全）

`.env.example` 是**被 git 跟踪的模板文件**，会随仓库推送到 GitHub。排查中发现该文件曾被填入真实 `WX_APPSECRET`。

**处置**：
- 已恢复为占位符 `WX_APPSECRET=你的小程序AppSecret`；
- 经 `git log -S` 核查，该密钥**从未进入任何历史提交**，仅在未提交的工作区存在，未造成泄露。

**规范（务必遵守）**：
1. `.env.example` 只放占位符，永远不放真实值；
2. 提交前执行密钥扫描：`git grep -n "<真实secret>"`，无输出方可提交；
3. `.env` 必须被 `.gitignore` 覆盖（当前已覆盖）。

## 八、2026-11-03 补充：登录凭证（token）上线须知

云函数已改为「服务端签发 token」的身份模型，部署时有三点与首次部署不同：

1. **必须重新上传部署 `yqsss-auth`**。仅改环境变量不生效，旧版本代码仍按 `event.openid` 认身份。
2. **必须先建唯一索引再放量**。`users.openid` 已改为唯一索引，若库中已存在重复 openid，索引会创建失败。先跑一次聚合查重（脚本见审计报告 §9.5），确认无重复后再上传索引。
3. **本次是破坏性协议变更**。旧客户端只传 `openid`、不带 token，会收到 `7001`。当前小程序未正式发布，云函数与客户端同窗口更新即可。

`AUTH_TOKEN_SECRET` 为可选环境变量：不配置时回退使用 `WX_APPSECRET`，现有部署无需新增配置。单独配置的价值是「重置 AppSecret 不会让全部 token 一起失效」。

验证方式：小程序内重新登录一次，成功后 `users` 表 `lastLoginAt` 更新、`achievements` 表的 `openid` 与本地一致；若返回 `7001/7002/7003`，按上文 `§9.3 错误码约定` 对照排查。
